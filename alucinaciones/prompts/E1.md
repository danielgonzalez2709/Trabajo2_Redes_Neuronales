## Qué construir
1. Esqueleto Next.js + TypeScript en `app/` con `output: "export"` (sitio estático), `npm --prefix app run dev` levanta y
   `npm --prefix app run build` genera el sitio estático. Usa la versión estable más reciente de Next.js compatible con
   Node 24 que puedas instalar; fija versiones exactas en `app/package.json` y versiona `app/package-lock.json`. Añade a
   `.gitignore` lo necesario (`app/node_modules`, `app/.next`, `app/out`) — si `.gitignore` de la raíz no lo cubre, usa
   `app/.gitignore`.
2. `app/lib/preprocesar.ts`: función pura que, dada la sección `preprocesamiento` del JSON y un registro de entradas crudas
   (como en `casos_paridad`), devuelve el vector de características en el mismo orden y con las mismas transformaciones que
   `Preprocesador.transform` de Python (recortes, imputación, transformaciones, one-hot/categorías, escalado: lo que haga
   realmente el código Python; no supongas, léelo). Tipos explícitos del contrato en `app/lib/contrato.ts`.
3. `app/lib/modelo.ts`: forward de `red.capas` (W en formato salida × entrada como `torch.nn.Linear.weight`, `b`,
   activaciones `relu`, `leaky_relu`, `tanh`, `identidad` con los mismos parámetros que Python — verifica la pendiente de
   leaky_relu en el código de B si aparece) → logit → PD con sigmoide numéricamente estable; puntaje con el bloque
   `scorecard` exactamente como lo calcula Python (sin redondear); percentil del puntaje en `poblacion.percentiles_score`
   (define la regla y documéntala; no forma parte de la paridad).
4. Prueba de paridad con Vitest (`npm --prefix app test`): para **cada** modelo (`logistica` y `mlp`) recorre las 1 000 filas
   de `casos_paridad_{modelo}.json` y exige |PD_TS − PD_Py| < 1e-6 y |score_TS − score_Py| < 1e-3 en todas; reporta el
   máximo de cada diferencia. Añade además pruebas unitarias pequeñas (una capa a mano, valor faltante, categoría no vista
   si el contrato lo contempla).
5. Página mínima `app/app/page.tsx` que cargue los dos JSON y muestre, para los `valor_defecto` de `entradas`, la PD y el
   puntaje de cada modelo (sin diseño todavía: la UI completa es E2). No incluyas ningún aviso por ahora (decisión
   pendiente del integrante).
